# CSI-Guard 기능정의서 (HOME 서비스)

## 1. 문서 개요

### 1.1 목적

본 문서는 CSI-Guard(Wi-Fi CSI 기반 비접촉 낙상 감지 관제 시스템) 중 **HOME 서비스**(가정용, 단일 거주자·단일 물리 기기)에서 실제로 구현되어 동작하는 기능을 화면·동작 단위로 정의하고, HOME 서비스가 연동하는 로컬 백엔드의 API를 명세하기 위해 작성한다. 계획 중이거나 미확정인 기능은 포함하지 않으며, 화면상 존재하지만 동작이 없는 스텁(Stub)은 "미구현"으로 명시적으로 표기한다.

### 1.2 시스템 구성 개요

HOME 서비스는 가정에 설치된 단일 ESP32-C5 수신기로부터 CSI 데이터를 수집해 낙상·재실을 감지하는 로컬 Python 백엔드(`backend/`)와 연동한다.

| 구성           | 설명                                                                                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 프런트엔드     | 웹 대시보드(`src/`). 로컬 백엔드에 HTTP/WebSocket으로 연결되어 실데이터를 표시                                                                                                                                    |
| 로컬 백엔드    | `backend/main.py`(FastAPI), `http://127.0.0.1:8000`에서 실행. 시리얼로 수신기와 통신하며 재실/움직임 감지(항상 동작)와 딥러닝 기반 낙상 감지(모델 로드 성공 시에만 동작)를 병렬로 수행                            |
| Fallback(Mock) | 로컬 백엔드 프로세스가 실행되지 않았거나 응답하지 않는 경우, 장치 연결·캘리브레이션·알고리즘 설정·알림 수신자 관리 등 일부 화면은 프런트엔드 내 시뮬레이션(Mock)으로 자동 대체되어 UI 확인이 가능하도록 되어 있다 |

같은 화면이라도 **로컬 백엔드 연결 여부**에 따라 실데이터(Real) 기반으로 동작하는지, 시뮬레이션(Mock)으로 대체되는지가 달라진다. 본 문서의 기능정의서 표는 각 기능 설명 앞에 아래 표기로 이를 구분한다.

### 1.3 표기 범례

| 표기                      | 의미                                                           |
| ------------------------- | -------------------------------------------------------------- |
| `[공통]`                  | 백엔드 연결 여부와 무관하게 동일하게 동작                      |
| `[HOME]`                  | HOME 계정에서 노출/동작(백엔드 연결 여부와 무관한 화면 요소)   |
| `[HOME, backend 연결 시]` | 로컬 백엔드(127.0.0.1:8000) 프로세스가 응답하고 있을 때만 해당 |
| `[HOME, backend 미연결]`  | 로컬 백엔드가 응답하지 않을 때 자동으로 대체되는 동작          |
| `(Mock)`                  | 실서버 없이 프론트엔드 내 시뮬레이션 데이터/로직으로 동작      |
| `(Real)`                  | 로컬 Python 백엔드와 실제 HTTP/WebSocket 통신으로 동작         |
| `(미구현)`                | 화면/메뉴는 존재하나 실제 기능이 없는 스텁                     |

## 2. 용어 정리

| 용어                            | 설명                                                                                                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CSI (Channel State Information) | Wi-Fi 신호의 채널 상태 정보. 사람의 움직임에 따라 진폭/위상이 변화하는 것을 이용해 비접촉으로 움직임·낙상을 감지하는 원천 데이터                                                                                         |
| MV (Moving Variance)            | "움직임 감지" 지표. CSI 진폭 신호의 이동 분산 값으로, 임계값 초과 시 SUSPECT/FALL 상태로 전이하는 판단 근거가 됨                                                                                                         |
| WANDER                          | 재실(在室) 판단을 보조하는 이동성 지표. 개별 사용자의 캘리브레이션된 baseline 대비 비율(`wander_ratio`)로 평가                                                                                                           |
| 상태 머신 (State Machine)       | 낙상 판정 상태: `IDLE`(대기) → `SUSPECT`(의심) → `FALL`(낙상) → `COOLDOWN`(냉각중) → `IDLE` 순으로 전이                                                                                                                  |
| 재실/퇴실 (Presence)            | `PRESENT`(재실)/`ABSENT`(퇴실). 최근 활동 시각(`last_activity_at`) 기준 `presence_timeout_s` 경과 여부로 판단                                                                                                            |
| HOME                            | 가정용 서비스 유형. 단일 거주자·단일 물리 기기를 대상으로 하며, 계정 역할은 항상 `USER`                                                                                                                                  |
| Primary Device                  | 한 거주자에게 여러 기기가 매핑된 경우 대표로 지정된 기기. HOME 계정은 물리적으로 로컬 백엔드와 연결 가능한 기기가 1대뿐이므로, 실데이터가 반영되는 기준 기기이기도 함                                                    |
| 캘리브레이션 (장치 재설정)      | 장치별 `presence_mv_threshold`(움직임 임계값)/`wander_baseline`(재실 baseline)을 재측정하는 4단계 절차: `LEAVING`(공간 비우기) → `WAITING_ACK`(장치 응답 대기) → `WAITING_AGC`(AGC 보정 대기) → `MEASURING`(기준값 측정) |
| 판정 임계값 (DL 임계값)         | 낙상 확률(`proba_fall`)이 이 값을 넘으면 낙상으로 판정하는 딥러닝 모델의 임계값. 움직임 임계값과는 별개의 스케일                                                                                                         |
| 움직임 임계값 / 재실 baseline   | `presence_mv_threshold`/`wander_baseline`. 재실·움직임 감지 전용 값으로, 낙상 확률 임계값과 무관                                                                                                                         |
| DL 모델                         | `backend/detector.py`의 `DualBranchResNet` 기반 낙상 분류 모델. S3 스칼로그램 + PCA-ACF 특징을 입력으로 사용하며, 체크포인트 로드 실패 시(`--no-model` 포함) 비활성화되고 재실/움직임 기능은 영향받지 않음               |
| ntfy                            | HOME 계정의 실제 푸시 알림 채널. 사용자가 ntfy 모바일 앱에서 구독 코드(topic)를 구독하면 낙상 발생 시 백엔드가 직접 푸시를 전송                                                                                          |
| MQTT                            | UI에 통신 방식 카드가 존재하나 현재 비활성화 상태(로컬 시리얼 구조 확정 전까지 미사용)                                                                                                                                   |
| 알림 게이트웨이                 | 낙상 알림 수신자를 관리하는 화면(`/notifications`)의 명칭                                                                                                                                                                |

## 4. API 명세

### 4.1 개요

- 대상: HOME 계정용 로컬 Python 백엔드가 제공하는 API. Mock(Fallback) 동작은 서버가 없는 순수 클라이언트 로직이므로 API가 존재하지 않는다.
- 총 20개 엔드포인트(HTTP 19개 + WebSocket 1개).
